## 1. Parameters: nothing searches for a value

- Axis cards state constraints as intervals `{min, max, basis, varies_with?}` (`contracts/schemas/common.schema.json:440-475`, `axis.schema.json:210`).
- S4 (`simulation_agent/src/synthesis.py:49-101`, `intersect()`) takes the highest floor and the lowest ceiling; an empty result names the two colliding axes. The operating point is "a judgement passed in rather than computed" (`synthesis.py:11-16`): a hand-written `OPERATING_POINT` table (`synthesis.py:194-262`) or `configs.operating_point()`, e.g. `dt = tau_d/1000`, `T = 10*tau_d`, labelled the person's standing default. Rejected options are prose. The priority order comes from the goal card; with none, S4 asks the person. S4 makes no new numbers.
- Explore mode treats a difference under 10× as a tie; confirm mode compares numerically.
- Sweeps are fixed grids (`plan.schema.json:460-537`): levels are corners the person set or are `assumed:a_sweep_grid`; an over-budget sweep is refused with a hand-written "narrow the sweep" option.
- Bisection exists only in standalone scripts outside the card pipeline (`simulation_agent/src/double_well_map.py:55-115`, `double_well_points.py:34`), root-finding on a closed form and writing JSON, no cards.
- Microscope focus (`microscope_runtime/src/focus_search.py:128-162`): a coarse grid, then a fine grid around the brightest frame, extended only with the operator's OK; the z floor and ceiling are the person's per-lens limits in `safety.json`.
- Not in SMA: any optimiser, Pareto or multi-objective computation, adaptive parameter choice inside S3–S5, or "find a value near a known range". Bounds always come from a card, an entry, the envelope or the person.

## 2. Numbers and grades

- A number (`common.schema.json:48-111`) requires `name, value, unit, source, grade`; optional `at`, `precision` (order of magnitude or significant figures), `formula`, `inputs`, `derived`, `symbol`, `origin`, `note`. `value` is one number.
- Source kinds are eleven prefixes: `measured, calibration, spec, prior_run, literature, operator_read, operator_recall, computed, simulated, assumed, kb`.
- The grade is derived in code (`SOURCE_GRADE`, `contracts/validate.py:214-226`), no table file: measured E1; calibration E2; spec, prior_run, literature, operator_read E3; operator_recall and assumed E5; **computed and simulated get `max(E4, worst input)`**; `kb` inherits the cited entry's grade. `grade_tag` ranks sources inside E3 (peer_reviewed > textbook > vendor_spec > preprint).
- No range, bound or tie value kind: a range is `validity` or an interval; a tie is a comparison verdict with its own grade.
- Conflicts are marked by hand and never resolved: the librarian writes `conflict_with` on both entries and keeps both; `kb_conflicts` only reads the marks; "which one applies is decided by the conditions, by the caller".
- Checks: 2 units, 3 source and grade with the E6 ban, 21 grade derivation, 24 calibration validity, 43 entry grade, 67 entry units; **17 recomputes derived values**; 25 `kb_refs`; 39 estimates justified.

## 3. Knowledge flow

- `kb_candidate` does not exist in SMA. Ingest runs one source at a time in the librarian's session, committed by seat `librarian`: a source record in `kb/sources/` and a note in `kb/distilled/`; one claim per file in `kb/entries/`; `kb_index.py` rebuilds `index.json` and the content hash `kb_version`; one line in `queries/ingest_log.jsonl`.
- `kb/staging/` holds flat tables awaiting split; `kb/wiki` and `kb/guides` are generated and not citable. Snapshots go to `kb/exports/snapshot_<agent>.json` and each agent copies its own into `envelope/snapshot.json` under its seat.
- New facts from execution agents: a result card for measured values, which only the librarian turns into an entry; and a findings file `<agent>/findings/<seat>-<YYYYMMDD>.json` whose items carry `for_store: true` as the seat's proposal to enter one. That is the closest thing to a `kb_candidate`; the librarian checks the source and promotes it. Device self-reports enter as `measured:<run_id>` E1 under check 85. Prior-repository numbers are capped at E3 and never become safety limits.

## 4. Experience and failure memory

- `failures.jsonl` lives in each agent folder and the bridge. A line requires `at, kind, detail` and exactly one of `qid | task | occasion`; `kind` is one of `validator_failure, refusal, deviation, scope_voided, success, abandoned_attempt`; `detail` is free-form, and a refusal carries `what, why, what_is_left, closes_by, who_decides`. No schema file; check 29 validates the keys. `rulings.jsonl` records rulings on prior-repository items.
- Lines are written by the session by hand; no hook writes one (the end-of-turn hook only reminds).
- **Nothing recalls a failure when a task starts**: no instruction says to read `failures.jsonl` first and nothing matches deterministically. The designed route, lessons distilled into `kb/lessons/`, was not built; check 30 reports "no lessons yet".
- `incidents.jsonl` is not in the current tree (see 5).

## 6. The bridge

- Carries one side's plan or result card to the other inside an envelope "without changing a character", tracks rounds and turns, authors nothing. Envelope kinds: `ask_simulation`, `ask_experiment` only, `author: bridge`, empty `numbers[]`; trigger `plan_completion` or `human`; a result crosses only on `human`; operation plans never cross.
- Gates: unit consistency and answerability, each `yes | no | undeclared`; `no` becomes a refusal card, `undeclared` a hold (`state: held, turn: human`); an integrity check via `r<N>_hashes.json`; duplicate-round blocking; escalation when the same `(reason_code, parameter)` repeats.
- Delivery into `<agent>/inbox/<thread>/`, envelope plus `.md`; the envelope's presence is the turn. Each thread has `bridge/threads/<thr>/status.json`. Its only code is the read-only board `contracts/bridge_board.py`.
- Degraded: a card records what it ran without (`degraded: ["librarian_agent"]`); the envelope must carry the payload's `degraded`, dropping it fails check 8; `degraded: []` may rest only on a log line under the round's own `caller_id`.

## 7. Safety

- The only safety file is `microscope_runtime/envelope/safety.json` (policy version 9, target `bench`): laser voltage, optical power, objective clearance, piezo x/y/z, tweezers position, strength and step, per-lens focus z, `pfs_not_engaged`. `approvals/` and `envelope/console_login.json` are the person's. Four acts stay the person's own: signing a plan hash, writing a safety value, handing a session the bench, paying for a service.
- Deterministic readers in `microscope_runtime/src/operator.py`, in order inside `run()`: `load_safety` (absent means Refusal) → `authorise` (plan id and revision match, then `plan_hash == validate.plan_hash(plan)`; irreversible actions refuse scope approvals) → console gate → run lock (`acquire` never waits) → `resolve_limits`, `check_envelope` (refuses on breach), `check_operation_points`, `check_trap_steps`. `plan_hash` is sha256 of canonical JSON with `status` removed. An approval is `{plan_hash, approved_by, author: human}`.
- Held and stop states are released only by the person: a held, escalated or closed bridge thread; a manual-sheet lockout; scope approvals can be voided.

## 8. `seat_commit.py` and the validator

- `contracts/tools/seat_commit.py` takes the committer from `HEAD:contracts/seats.json` and sets `GIT_COMMITTER_NAME/EMAIL`; `--seat human` requires `--persons-word` (a `Persons-word:` trailer), other seats are refused it; `--removes-check N` adds a `Removes-check:` trailer, and the pre-commit hook refuses any undeclared removal of a `def check_NN_`; commits only the named paths via `commit --only`; no amend, force or `--no-verify`; reads the commit back; `--push` fetches, refuses if behind, then pushes.
- Checks are `def check_NN_name`, run from an explicit `CHECKS` list; check 42 requires plan.md §8, the defs and the list to agree; 92 checks registered, numbered 1–98, gaps 89 and 91–95 from the harness removal; numbers are never reused.
- `contracts/examples/rejected/` holds 185 entries: 93 flat `bad_*.json` cards that must fail some check and 92 group folders `checkNN_<slug>` that must fail check NN specifically; check 64 requires every file there to be a subject or an input. `--expect-fail` exists. `contracts/history_fixtures.py` builds temporary git repositories for the checks that read history.
