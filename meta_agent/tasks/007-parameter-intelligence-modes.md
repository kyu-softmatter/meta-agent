**Goal:** a `parameter_sheet` row reaches its recommendation stage by one of six modes chosen by a rule, never by the model: `lookup`, `scale`, `interval`, `neighbourhood`, `tradeoff`, `gap`. Every `computed` row can be recomputed by the validator from its `basis` through a registry of helpers, and its grade is the worse of E4 and its inputs. One offline adapter gives the first real values. This is M3 of plan.md 12 and 5.3, less the `protein` card format, which the example set already fixes.

**What is settled (the person, 2026-11-08, plan.md 14-26 and 14-12):** the six modes and the rule that picks them; a safety-relevant row gets a value from no mode; `recommendation {mode, basis, candidates, frontier, chosen_by}` on the row and `objectives[]` on the sheet; the helper registry; the recompute check; first-order uncertainty and worst-input significant figures; `chemicals` first and NIST WebBook second; `computed` grade `max(E4, worst input)`.

**Method (recommended, not settled):**
- Design seat, schema and vocabulary: `parameter_sheet.schema.json` gains `recommendation` on a row (`mode` one of six; `basis[]` naming helper ids and input row names; `candidates[]` and `frontier[]` as rows with `chosen_by: human | rule:<id>`; `chosen_by` required when `mode` is `tradeoff`), `objectives[]` on the sheet (`name, parameter, direction: min | max | target, target?, source`), and `basis` on any `computed` row. `grades.json` gains a row `computed → max(E4, worst input)` with the old flat row kept under `retired_on`; check 2 reads `basis`, looks up each input row's grade and compares. `contracts/registry/helpers.json`: `{id, expression, inputs: [{name, unit}], output_unit, validity, source, note}` with the expression in a small language the validator evaluates (names, numbers, `+ - * / ^`, `log10`, `sqrt`, `abs`, `min`, `max`, parentheses; nothing else; a test proves that the evaluator refuses anything else). First helpers: Re, Wi, De, Pe, Ca, Bingham and Courant numbers; cone-plate and parallel-plate stress and rate factors; minimum torque → minimum stress → minimum measurable viscosity at a rate; the inertia limit; the gap-to-particle ratio. Each cites its source in `source`.
- Design seat, checks: check 4 (a `safety_relevant: true` row has `value: null` or `author: human`, in any stage) and check 19, the recompute check (every `computed` row with a `basis` is recomputed through `helpers.json` from the named input rows, in the units the helper states, and must agree to the row's stated `uncertainty` or, without one, to its significant figures; a `computed` row without `basis` fails; a helper id not in the registry fails), each with rejected fixtures under `check04_*/` and `check19_*/`, and an accepted example sheet with one row per mode. plan.md 8 marks 4 and 19 implemented. The check on `tools.lock.json` of 14-23(c) is `005`'s; if `005` has not landed it when this task needs the pin, it lands here.
- Meta seat, modes: `src/parameters/modes.py` picks the mode by this rule, in order: a safety-relevant row → no value, `gap` with `requires: the person's value`; a source row under matching `conditions` → `lookup`; a source row under other conditions and a helper whose inputs are present → `scale`; two or more `objectives` on the same parameter, or constraints that leave no interval → `tradeoff`; an anchor row and a request for a value near it (the goal names `near:<row>`) → `neighbourhood`; one objective and constraints → `interval`; otherwise `gap`. `interval` intersects the constraints as SMA's S4 does, each bound citing its row, and states one point by the log-midpoint rule named in `basis`; `neighbourhood` scans ± one decade in half-decade steps around the anchor, filters by the constraints, and writes a `gap` whose `requires` names the measurement or calibration that would pin the value; `tradeoff` evaluates the objectives on a log grid, keeps the Pareto set as `frontier[]`, marks the knee, and leaves the row `UNDECIDED` with `chosen_by: human`. No mode writes a number the row cannot cite.
- Meta seat, helpers and uncertainty: `src/parameters/helpers.py` evaluates the same registry with the same evaluator the validator uses (one module under `contracts/` imported by both, so a computed value and its check cannot disagree), propagates first-order uncertainty from the inputs' `uncertainty`, and rounds to the worst input's significant figures.
- Meta seat, adapter: `src/sources/chemicals_adapter.py` returns water and glycerol-water viscosity and density against temperature and mass fraction as rows with `source: database:chemicals@<pinned version>`, `value_kind: correlation`, the correlation's validity on `valid_range` and its conditions on `conditions`; the adapter is the only module that imports `chemicals`, and the Designer runs with the adapter `degraded` when the package is absent. `src/sources/nist_webbook.py` is a stub that returns a `gap` naming the URL it would read, so that the comparison trial of plan.md 5.3 has its second seat ready; it fetches nothing in this task.
- Tests: one sheet per mode on fixtures (the echo request plus a fixture rheometer `tool_profile` with torque, gap and temperature limits); the picked mode is the expected one; `tradeoff` leaves the row `UNDECIDED`; `neighbourhood` writes a `gap` with `requires`; the recompute check passes on a correct Wi row and `--expect-fail` rejects a wrong one; a computed row with an E5 input is graded E5; the adapter's water viscosity at 20 °C lies within the correlation's own stated uncertainty of the handbook value kept in the fixture; two runs write identical sheets.
