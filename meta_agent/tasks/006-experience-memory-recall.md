**Method (recommended, not settled):**
- Design seat: `case.schema.json` lets a `condition_tags` item be `name:value` or `name:lo..hi` (a documented pattern; `lo` and `hi` are numbers, scientific notation allowed, unit on the name as `shear_rate_1/s`); check 5 (every `case_ref` resolves in `cases/index.json`, every `case_gaps[].searched` is non-empty) and check 8 (`falsification`, `count`, `cue`, `cause_status` present; `confirmed` only with an `evidence` item of kind `run` or `commit`; `cause_class` in `case_classes.json`), each with at least two rejected fixtures under `../../contracts/examples/rejected/check05_*/` and `check08_*/`; plan.md 8 marks them implemented.
- Meta seat, recall: `src/cases/recall.py` loads `cases/index.json` and every case; level 1 is a weighted intersection of the full signature (`science_task`, `executes`, `instrument`, `engine`, `methods`, `observables`, `parameter_names`, `cause_class`, `condition_tags`), level 2 is `cause_class` and `executes` alone; a range tag matches another range or a point by interval overlap on the same name; hits are sorted grade → `count.supports` → id; the result names the level that matched; a miss is `{searched: <the signature as searched>, requires: ...}`. No model call, no text similarity (plan.md 14-7). Weights are constants in the module with a comment, not a threshold the person must set.
- Meta seat, injection: `src/intake/goal.py` calls recall after the goal's signature is known and writes `case_refs` (id, level, one line of the `cue`) or `case_gaps`; the same call is made again where A4 and A5 will read it (today, the Designer's spec and build steps), each recording what it searched.
- Meta seat, seeds: `src/cases/seed_sma.py <path-to-sma-checkout>` reads the four `failures.jsonl` and the historical `incidents.jsonl`, writes one draft case per line under `cases/sma/<agent>-<n>.json` with `source_repo_commit: d68ee7d2` (or `7bc5a0f9~1` for incidents), `source_agent`, `source: prior_run:soft-matter-agents@<sha>` at grade E3, `cause_status: observed`, `status: draft`, a verdict drawn by rules written in the script and shown in its docstring (for example: `kind: success` → `drop`; a `refusal` with `what_is_left` → `transfer`; a line whose detail names only the microscope bench → `downgrade`), the `what_happened` copied, and `cue`, `lesson`, `falsification` drafted by the model from the line, each marked `draft` until the person confirms. The verdict and its rule go on the case's `note`. The script is deterministic for everything but the three drafted fields and is re-runnable; a second run changes no existing file.
- Meta seat, promotion: `src/cases/promote.py` lists cases whose `cause_status` is `confirmed` and whose `count.supports` is at or above N read from a flag (no default; without the flag it lists candidates and writes nothing) and emits a draft `kb_candidate` or a draft `reshape` proposal. It lands nothing.
- Tests: a fixture store of five hand-written cases under `tests/fixtures/cases/` (one with a range tag); recall finds the expected case at level 1, another at level 2, records a gap for a third signature, and returns the same result on two runs; a range tag overlaps a point inside it and not one outside; the seed script on a three-line fixture `failures.jsonl` writes three drafts with the expected verdicts; a `v2_agent_goal` written with `case_refs` passes `validate.py`.

**Done when (read off a run):**
- `python contracts/validate.py --expect-fail` rejects every new fixture under `check05_*` and `check08_*`; `python contracts/validate.py` prints `0 failed` over the whole tree with the seed cases present.
- `python -m meta_agent.src.designer` on the echo fixture request writes a `v2_agent_goal` carrying `case_refs` or `case_gaps`, and a second run writes an identical card.
- `cases/index.json` lists every case; `cases/sma/` holds one draft per source line with its verdict and source commit; no case has a grade above E3 or a `cause_status` other than `observed`.
- `PYTHONUTF8=1 python -m unittest discover -s meta_agent/tests -t .` is OK.

**Must not:** call a model inside recall; add text similarity, embeddings or a vector index (plan.md 13, 14-7); set N or any threshold in code (14-15); mark a case `confirmed` or a seed `transfer` by anything but the rule shown in the script, and never confirm for the person; write into the soft-matter-agents checkout; write a number from a seed line as anything above E3; write outside `meta_agent/` (meta seat) or inside `meta_agent/src/` (design seat).

**Report:** ten lines or fewer — the two checks' fixture counts, the recall weights, the number of seeds per source file and per verdict, the `case_refs` or `case_gaps` of the echo goal, the verdict line, the test count.
