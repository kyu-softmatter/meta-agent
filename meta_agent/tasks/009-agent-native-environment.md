# 009 — The agent-native environment: seats, a shared working copy, the task queue, CI

**Status:** open, 2026-11-09. Opened by the design seat on the person's words (`../../docs/ideas/20261109.md`: the goal, then "결정만 먼저", "모두 허락", "그렇다"), which plan.md 14-29 records. The standing rule itself is already in the root `CLAUDE.md`, plan.md 9 and `contracts/seats.json`; nothing enforces or helps it yet. Goes before `010` and `006`–`008`, which three seats are meant to do at the same time.

**Seat:** a `design-…` seat: every part is under `contracts/`, the root, `.github/` or `meta_agent/tasks/`. Each part below is its own commit, in order; a part that adds a check lands its rejected fixtures in the same commit, watched failing first.

**Goal:** a session can sit down on a computer, become a seat, take a task nobody else has, work beside two other seats in the one working copy, commit only what is its own, leave a note for another seat, and be judged by the same gate on GitHub as on the computer, all without the person's hand. The person's part is what plan.md 9 keeps human-only.

**What is settled (the person, 2026-11-09):** the scope (the repository as the seats' environment, and the product); decisions only first, unattended runs later; self-registration of a seat under the rule; a task claim as a commit; the gate in GitHub Actions; the design, meta and harness seats at the same time on one computer. No worktrees, as before.

**Inputs:**
- `../../plan.md` 8 (check 6), 9, 14-5, 14-23, 14-29; `../../CLAUDE.md`; `../CLAUDE.md` ("Working habits").
- `../../contracts/seats.json` (`names`, `self_registration`, `concurrent`), `../../contracts/validate.py` (`check6_changes`, `IMPLEMENTED`, how `--staged` reads the index), `../../contracts/hooks/pre-commit`, `../../contracts/records.json` (what is append-only), `../../.claude/settings.json` (the edit hook), `../../bootstrap.py`.

- The task files `001`–`009` here, whose `**Status:**` and `**Seat:**` lines the index must agree with.

**Method (recommended, not settled), in this order:**
1. **The seat command.** `python bootstrap.py seat <role> [--machine <tag>]` reads `contracts/seats.json`, takes the machine tag from the flag or from `git config meta-agent.machine` (a clone's own setting; a tag not listed under `names` is refused with "the person gives a new machine its tag"), finds the next free `n` for the role, machine and today's date, and prints the name, the entry to add (paths and excludes copied from the role's row) and the `seat_commit.py` line that registers it. It writes nothing unless `--write` is given, and then only the entry. `seats.json` gains `roles: {design, meta, harness}` with each role's `paths` and `excludes`, and every existing seat must equal its role's row (the first assertion of the new check).
2. **The commit tool.** `contracts/tools/seat_commit.py --seat <name> -m <message> <path> [<path> …]`: looks the seat up in `HEAD:contracts/seats.json` (or accepts a seat absent there only when the commit is its own registration), sets `GIT_COMMITTER_NAME` and `GIT_COMMITTER_EMAIL` for that one commit, keeps the author as git has it, runs `git commit --only -- <paths>` so that another seat's staged or unstaged work is untouched, never passes `--amend`, `--no-verify` or a force, and prints the hash, the committer and the paths read back from the commit. Verify first that the pre-commit hook's `validate.py --staged` judges the temporary index `--only` builds and not the shared one; if it does not, the tool runs the staged check itself on the named paths before committing. No `--push`: whether a seat pushes on its own is the person's (14-29(g)).
3. **Check 6, self-registration.** A commit whose only change is one new entry in `seats.json` passes for a committer not yet registered when the entry's email is the committer's, the name fits the pattern with a listed machine tag and today's or the commit's date, the role is one of `roles`, `paths` and `excludes` equal the role's row, and `seated_by` starts with `self`. Rejected fixtures (history fixtures): a self-registered seat with one extra path; with an unlisted machine tag; an entry for another identity added by a non-design seat; a registration commit that also touches another file. An accepted history fixture: a meta seat registers itself, then commits inside `meta_agent/`.
4. **The task queue as data.** `meta_agent/tasks/index.json`, the design seat's: one row per task `{id, file, status: open | done, role, depends_on[], opened, done_commit}`. Claims are separate so that no two seats edit one file: `meta_agent/tasks/claims/<task id>-<seat>.json` `{task, seat, claimed_at}`, append-only (`records.json`), in every role's paths. Check 20 (19 is reserved for `007`'s recompute check): every task file has a row and its `**Status:**` word agrees; a `done` row names a commit that exists; a claim names a task that is `open`, whose `depends_on` are `done`, and a registered active seat of the task's role, and its file was committed by that seat; a second claim of one task by another seat fails; a claim on a `done` task is only reported. Rejected fixtures for each. `../CLAUDE.md` "Working habits" then says: take the lowest open task of your role that is unclaimed and whose dependencies are done, and claim it in its own commit before you start. The index gets `005`–`010` with `009 → 010 → 006 → 007 → 008`.
5. **Notes between seats.** `meta_agent/inbox/seats/<YYYYMMDD>-<from seat>-<n>.json` `{from, to_role, task, asks, answers: <note id> | null}`, one file per note, append-only, the folder in every role's paths; a reply is a new file whose `answers` names the note. Check 21: `from` is the committer of the commit that added the file; `answers` resolves; a note with no reply is PENDING, named with its `to_role`, so that a seat that starts sees what waits for its role. This replaces "write the proposal in a task or a card and leave the landing to the design seat" for a meta seat that needs a schema or a check changed. It is not the bridge of M8.
6. **CI.** `.github/workflows/gate.yml`, on every push and pull request: checkout with the full history (`fetch-depth: 0`, since checks 6 and 7 read commits), Python as `bootstrap.py` requires, `PYTHONUTF8=1`, then `python contracts/validate.py`, `python contracts/validate.py --expect-fail` and `python -m unittest discover -s meta_agent/tests -t .`. No secret, no external tool install, no write permission. `.github/` joins the design role's paths. The run's verdict line is the same line a seat prints locally.
7. **Two seats, one folder, read off a run.** With two sessions open on this computer as different seats: seat A leaves a card half-written; does seat B's edit hook (`validate.py --quiet` over the whole tree) fail? Does `seat_commit.py` from B leave A's staged files staged and uncommitted? Do both commits carry their own committer? What is observed goes to `../../docs/ideas/` as a finding with the commands; if the hook stops the other seat, the recommendation (the hook judges the files the seat changed, the commit hook and CI still judge everything) goes to the person, not into `.claude/settings.json`.

**Done when (read off a run):**
- `python bootstrap.py seat meta` on this computer prints a name of the pattern and an entry equal to the meta role's row; with an unlisted `--machine` it refuses.
- A `meta-…` seat registers itself through `seat_commit.py` and `python contracts/validate.py` prints `0 failed` with check 6 judging that commit; `--expect-fail` rejects every new fixture of checks 6, 20 and 21.
- `tasks/index.json` lists `001`–`009`; a claim file for one open task passes, and a second claim of it by another seat is a rejected fixture.
- Two commits made from two sessions in this working copy carry two committers, and neither contains a path of the other's.
- The workflow's run on GitHub ends with the same `VERDICT PASS` line as the local run at the same commit (the push that triggers it is the person's word).
- `PYTHONUTF8=1 python -m unittest discover -s meta_agent/tests -t .` is OK.

**Must not:** give a seat a path outside its role's row, or accept a new role or machine tag without the person; register a seat for another session; create a worktree or a branch; push, force, amend or skip the hook from the tool; put a secret or a write token in the workflow; change `.claude/settings.json` hooks or permissions without the person's word (a standing configuration); start unattended runs (14-5); touch `meta_agent/src/`.

**Report:** ten lines or fewer — the seat name the command gave, the fixture counts of checks 6, 20 and 21, the index rows, what the two-session run showed about the hook and the index, the workflow's verdict line, the local verdict line, the test count.
