**Method (recommended, not settled):**
- Design seat, the tool `contracts/tools/testfolder.py`. Where the test folder and the log folder are is this computer's and is read from the clone's own git configuration, as the machine tag is; a tool in a pushed repository names no folder of the person's.
  - `make` writes one *run* under the test folder, a folder whose name is a date and a count and is never used twice, since the application keeps a session's history and memory by the path it was opened in, and a path used again would hand a later test what an earlier one left. The run holds a clean copy of the repository at its committed head (a clone that can fetch from the working copy and can push nowhere, set up as `begin-session` asks of a clone) and a copy of each chosen bundle, the bundle alone, its hash equal to its build card's. A file at the top of the run says what was copied from where and every file's hash. A run is entered in the log folder the moment it is made.
  - `collect` copies, for every session that was opened inside the run, its transcript as the application wrote it, and beside it one line per tool call (the command, the file, the skill) and a summary read off the transcript: the model, the first and last time, the skills loaded, the files written and which of them lie outside the folder the session was opened in. For each bundle it writes which files were added, changed or removed against the hashes of `make`, with the files themselves; for the clone, the commits made, the difference from the head it was cloned at, and the gate's verdict line. A collection is a new folder each time and overwrites nothing.
  - `wipe` collects, then removes the run. It removes only a folder that carries the file `make` wrote, and nothing of this repository, of the log folder or of the application.
- Design seat, the session skill `test-outside-the-repository`: when a test is made, how a session is opened in it, that collecting comes before removing, and where each finding goes.
- Meta seat, the first test: one run with the newest build of each agent and the clone. In each bundle a fresh session with the brief the watches of `015` used, so that the two can be compared; in the clone a fresh session that is given what a person would give the Meta-Agent, a purpose in words and where the materials are, and nothing of how. A session in the run is opened by the person, or by the meta seat on the person's word; the watch of `rheo-fixture/0003` showed that a session opened by another session is also given the application's instructions for such a session.
- Meta seat, from a collection to the repository: each fault becomes a line in `../failures.jsonl`, a `case` when a cause is found, a change of template text or of `../src/` in a new version, or a note to the design role when a check, a schema, a session skill or a `CLAUDE.md` should change. Each names the run, the collection and the session it was read from; those are files on this computer and are not a record, as the copies of `015` were not.

**Waits for the person:**
- what the session in the clone is asked first: a request already in `../requests/` made again, or a new one on fixtures of a kind not yet built;
- which model and effort each test session runs on (`choose-session-level` recommends; the person's word holds);
- whether any part of a transcript may ever enter the repository. Until the person says so, none does;
- whether `wipe` should also remove what the application keeps for the sessions of a removed run (their transcripts and memory under the application's own folder). The tool does not; a run's path is never used again, so nothing of it reaches a later test.
